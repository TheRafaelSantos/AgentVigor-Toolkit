# From intent to a verifiable plan

Resolve meaningful ambiguity and define checks before implementing.

1. Read the request and relevant existing behavior. State intended outcome, constraints, and the available evidence. Ask one focused question only when its answer changes the work.

2. Compare viable designs by cost, risk, maintenance, and reversibility. Keep assumptions explicit. Reuse prior decisions and authorizations.

3. Write an ordered plan with affected files or resources, dependencies, expected results, and a concrete check per step. Record rollback for consequential changes.

4. Execute within the authorized scope. If a check fails, diagnose it before dependent work. Report verified behavior and unresolved decisions.
