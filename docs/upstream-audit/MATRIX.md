The audit covers **121 files**. The [source manifest](snapshot-files.json) records every path and SHA-256. [Content](CONTENT-AUDIT.md), [engineering](ENGINEERING-AUDIT.md) and [visual assets](visual-files.json) record purpose, dependencies, client applicability, recommended treatment and file-level evidence. Those initial audit decisions describe the source review. The delivery column below records what the candidate provides.

**Native** means the capability can be used through the relevant client or its shell. **Conditional** means it depends on available client controls, optional tools, project configuration or explicit service access. **Reference** means the resource is distributed as a reviewed example or documented upstream integration. Installation and file checks establish availability on disk. The discovery test in a fresh client session is a separate acceptance check.
